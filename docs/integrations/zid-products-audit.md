# مراجعة منتجات زد وإعدادات Standard Mapping

تاريخ المراجعة: 2026-11-03. هذه مراجعة للكود واختبارات محلية بعملاء Odoo وSupabase وهميين؛ لم تُنشأ منتجات أو كميات في حسابات حقيقية ولم يُنشر تعديل.

## النتيجة

لم يكن التنفيذ متطابقاً مع جميع إعدادات تاب المنتجات. كانت توجد أخطاء في تصنيف المنصة، هوية ومطابقة المتغيرات، ترتيب احتساب السعر، نوع المنتج في Odoo 15–17، التسجيل اليدوي، المخزون والمنتجات المجمعة. أصلحت المسارات المثبتة أدناه. لا تمثل الاختبارات المحلية شهادة تشغيل فعلي على سبع قواعد Odoo مختلفة.

## مسارات التنفيذ

- Webhook → enrichment من زد → Standard Mapping/custom mapping → `buildOdooValues` → `executeOdooOperation` → الكتابة والتسجيل.
- المنتج الأب ذو المتغيرات: `syncAsVariants` أو `syncAsSeparateProducts` بحسب الاختيار المحفوظ.
- حدث المنتج الفرعي: `syncChildVariantAsVariant` أو `syncChildAsSeparateProduct`.
- استيراد منتجات زد الأولي إلى `product.template` صار يستخدم نفس منفذ إعدادات المنتجات؛ بقية أنواع الاستيراد لم تتغير.
- الكميات تستخدم `product.product` حصراً، مع بقاء حارس أولوية Odoo عندما تكون مزامنته إلى المتجر مفعلة.

## مصفوفة الإصدارات

| الإصدار | نوع المنتج المخزني | بدون دفعات/سيريال | أسعار المتغيرات |
|---|---|---|---|
| 14 | `type=product` | `tracking=none` | سعر قالب + إضافات قيم الخصائص |
| 15–17 | `type=product` و`detailed_type=product` متوافقان | `tracking=none` | سعر قالب + إضافات قيم الخصائص |
| 18–19 | `type=consu`, `is_storable=true` | `tracking=none` | سعر قالب + إضافات قيم الخصائص |
| 20 | `type=consu`, `is_storable=true` | `tracking=false` | `lst_price` مستقل للمتغير |

في 15–17 يتحقق ORM من تطابق `type` و`detailed_type`؛ الكتابة السابقة للأول وحده قد تفشل أو تترك نوع واجهة أودوو غير متسق. في 14 و18+ يُحذف `detailed_type` من القيم. تعطيل تتبع المخزون يحترم الآن الاختيار حتى عندما يحمل المابنج `type=product` قديماً. الخدمة لا تحمل تتبع دفعات حتى لو كان إعداد التتبع مفعلاً.

## الأخطاء المصححة

| الإعداد/الحالة | المشكلة السابقة | التنفيذ بعد التصحيح |
|---|---|---|
| منصة زد | أحداث `.created` و`.updated` كانت تعيد تصنيف المنتج كسلة داخل منفذ المنتجات | استخدام المنصة المحددة للتسليم؛ تمييز الطفل في زد يعمل |
| السعر | اختيار `sale_price` أو `cost` كان يستبدل نتيجة الزيادة؛ بعض مسارات المتغيرات تختار سعر التخفيض رغم اختيار السعر العادي | اختيار المصدر ثم الزيادة ثم التقريب مرة واحدة؛ `sale_price=null` يعود للسعر العادي، والصفر يبقى صفراً |
| التكلفة | المصدر المحدد لا يتغلب على القيمة المبنية مسبقاً، ومسارات الطفل تكتب `cost` مباشرة | استخدام مصدر التكلفة المختار، بما فيه الصفر؛ عدم الكتابة فوق إعدادات الطفل بقيم خام |
| التقريب | `ceil` مع خطأ الفاصلة العائمة قد يحول 110 إلى 110.01 | سماحية رقمية صغيرة قبل التقريب |
| اللغات والوصف | قيم خام للطفل تلغي الاسم المختار وبديل الوصف | الاحتفاظ باسم الأب المختار مع لاحقة المتغير، وتنفيذ بدائل الوصف عند غياب الترجمة المختارة |
| تخطي الصور | إرسال `image_1920=false` كان يمسح صورة أودوو، ثم تعيد بعض مسارات المتغير كتابة الصورة | حذف حقول الصور من طلب الكتابة ومنع تنزيلها عند التخطي |
| ربط الموجود/الوحدات | العلاقات قد تُنشأ قبل وصول التنفيذ إلى إعداد التخطي | تمرير سياسة المنتجات إلى بناء العلاقات؛ `map_existing` و`uom.auto_create=false` يمنعان الإنشاء |
| المطابقة الصريحة | فشل الحقل المختار يرجع إلى اسم مشابه أو SKU غير مختار | عدم استخدام مطابقة منتج احتياطية غير مرتبطة بالحقل/الاستراتيجية المختارة؛ الروابط الدائمة والربط اليدوي تظل طرقاً صريحة لتحديد السجل |
| الربط اليدوي | رقم `product.template` يُستخدم أحياناً كأنه رقم `product.product`، والربط القديم قد يسبق الربط اليدوي الجديد | الربط اليدوي قبل التاريخ السابق؛ تحويل القالب إلى متغيره الصحيح، وعدم افتراض تساوي الأرقام |
| هوية المتغير المنفصل | يرث هوية الأب وباركوده أو اسمه المستخدم للمطابقة | تنظيف الهوية الموروثة، حقن هوية الطفل، وعدم السماح بدمج المتغير مع الأب أو متغير سابق في الوضع المنفصل |
| حقل مطابقة المتغير | البحث يقرأ أعمدة ثابتة ولا يقرأ الحقل المخصص المختار | تضمين الحقل المخصص في القراءة وفي تحديث هوية المتغير |
| عدد المتغيرات | `searchRead` افتراضياً يقرأ 100 سجل فقط | قراءة المتغيرات وقيم الخصائص على صفحات من 250، مع اختبار 251 سجلاً؛ تجنب معالجة صفوف صفرية في حل الأسعار |
| سعر المتغير 14–19 | كتابة `lst_price` تغيّر سعر القالب وباقي المتغيرات | حل إضافات الخصائص وكتابتها بطلب ORM واحد؛ فشل واضح إذا كانت أسعار التركيبات غير قابلة للتمثيل. تعديل طفل منفرد يحافظ على أسعار إخوته |
| الطفل المفقود | يُنشأ بدون مجموعة خصائص مكتملة أو يُسجل تخطيه إن لم يصل الأب | اشتراط مجموعة الخصائص، وإرجاع فشل قابل لإعادة المحاولة عند غياب الأب |
| السجلات والروابط | نجاح الأب لا يثبت دائماً الربط الدائم لكل متغير | تسجيل هوية كل متغير مع المنصة والمتجر بعد نجاح مزامنة الأسعار |
| العمليات المسموحة | بعض مسارات المتغيرات تنفذ upsert رغم منع الإنشاء/التعديل الفعلي | فحص العملية الفعلية قبل الكتابة وعدم اعتبار العملية المعطلة نجاحاً |
| كمية المنتج العادي | لا يمر بتسوية مخزون مثل المتغيرات | حل المتغير الحقيقي للقالب ثم تسوية كميته |
| كمية متعددة المخازن | إجمالي كمية قد يوضع في أول موقع | استخدام `stocks[].location` و`available_quantity` وربط المواقع؛ التحقق من جميع المواقع قبل أية كتابة، والفشل إذا كان موقع غير مربوط |
| كمية غير محدودة/خدمة/Kit | كتابة إجمالي كمية غير صالح أو كمية مستقلة للـKit | منع التسوية في هذه الحالات؛ كمية Kit مشتقة من مكوناته |
| فشل المخزون | مسارات تبتلع الخطأ وتكتب نجاحاً | فشل صريح عند تعذر تسوية المخزون أو حل المتغير الصحيح |
| مكونات المنتج المجمع | حذف السطور أولاً، وتجاهل مكون مفقود أو تحويل كمية صفر إلى 1 | حل جميع المكونات وكمياتها أولاً؛ تحديث كل سطور BoM في معاملة ORM واحدة؛ الحفاظ على القديم عند فشل الحل |
| إعداد BoM | أخطاء التصنيع تُبتلع | فشل واضح عند تفعيل BoM وتعذر تنفيذه؛ عدم اختيار BoM خاص بمتغير لتعديله كأنه BoM القالب |
| متجر مكونات BoM | احتمال اختيار أحدث بيانات اعتماد من متجر آخر | تقييد البيانات بمساحة العمل والمتجر المحدد؛ تمرير متجر التنفيذ بدل الاعتماد على جسم الحدث |

## إعدادات وحدود لا يصح إخفاؤها

1. **أسعار التركيبات في 14–19:** السعر يجب أن يساوي سعر القالب زائد مجموع إضافات الخصائص. مثال 100/110/120/130 قابل للتمثيل، لكن تغيير تركيبة واحدة إلى 999 قد يجعله غير قابل للتمثيل. استخدم `AS_SEPARATE_PRODUCTS` عندما تكون أسعار كل تركيبة مستقلة. Odoo 20 يسمح بالسعر المستقل.
2. **Lot/Serial:** إنشاء نوع المنتج وطريقة تتبعه مدعوم، لكن كمية إجمالية من زد لا تحدد أرقام الدفعات أو السيريال. التسوية الإجمالية ترفض برسالة واضحة بدل تعديل quant اعتباطي. يلزم مسار متخصص لمزامنة هويات الدفعات/السيريال.
3. **Dynamic Bundle:** اختيارات العميل ليست قائمة مكونات ثابتة. عند تفعيل BoM يظهر خطأ واضح بدل تمثيله Kit ثابتاً خاطئاً. المنتج المجمع الثابت يستخدم `group_products` و`item_quantity` كما في وثائق زد. المكونات المجمعة المتداخلة غير الموجودة يجب مزامنتها أولاً لمنع استيراد متكرر دائري.
4. **المخازن:** مخزون موزع يحتاج ربط المواقع. عند غياب `stocks` يظل مسار الكمية الإجمالية يستخدم الموقع الافتراضي، أو اختيار الموقع الداخلي القديم إن لم يحدد موقع؛ يجب التحقق منه في قاعدة العميل متعددة الشركات/المخازن قبل التشغيل.
5. **الصور:** تصحيح `skip` مثبت. خيار `all` ما زال لا يثبت مزامنة معرض صور متعدد؛ المسار الأساسي يبني صورة رئيسية، ولا توجد مزامنة كاملة لسجلات معرض `product.image` هنا.
6. **الضرائب:** الضرائب الثابتة و`skip` منطقياً منفصلان؛ قائمة ضرائب ثابتة فارغة تمسح الاختيار صراحة. `skip` يحافظ على ضرائب أودوو ولا يضمن إلغاء ضرائب أودوو الافتراضية. `auto_by_name` يعتمد على الربط المحفوظ `tax_mappings`؛ ليس محركاً كاملاً لإنشاء/مطابقة كل نسب الضرائب تلقائياً.
7. **الوحدات والشركات:** منع إنشاء الوحدة عند إغلاق الخيار مغطى. إنشاء وحدات جديدة وحقول التكلفة التابعة للشركة يحتاجان تحققاً فعلياً على وحدات Odoo وإعداد الشركة النشطة؛ اختيار `company_id` وحده لا يثبت صحة كل سياقات التكلفة متعددة الشركات.
8. **MRP والحقول المخصصة:** BoM يحتاج وحدة التصنيع وصلاحيات مناسبة. الحقول والإضافات المثبتة تختلف بين العملاء؛ نجاح اختبارات النسخ لا يثبت توفرها في كل قاعدة. استرداد أخطاء الحقول القديم في safeCreate/safeWrite باقٍ؛ قد يحذف حقلاً غير مدعوم من طلب الكتابة.
9. **الحذف:** إعدادات الأرشفة/الحذف لم تُعد صياغتها في هذه المراجعة. لم تُنفذ عمليات حذف حقيقية أو تدقيق دورة حذف كل متغير في أودوو. إزالة خيارات من زد لا تساوي تلقائياً حذف كل التركيبات التي يولدها أودوو؛ المزامنة الحالية تضيف/تحدث الخصائص ولا تنظف جميع التركيبات الزائدة.
10. **حدود المعاملة:** طلب تعديل BoM أو إضافات السعر نفسه ذري، لكن إنشاء القالب والخصائص والمخزون موزع على طلبات RPC مختلفة. قد يبقى قالب/خصائص إذا فشلت خطوة لاحقة؛ النتيجة تُبلغ بالفشل، وإعادة المحاولة تستخدم المطابقة والروابط الموجودة. لا توجد معاملة موزعة عبر زد وأودوو.

## التحقق

التفاصيل التنفيذية في `tests/unit/product-settings-execution.test.ts`، مع تحديث حالة الصفر في `product-variants.test.ts`. تغطي الاختبارات المصادر والزيادة والتقريب، نوع المنتج عبر 14–20، الحقول المخصصة والمطابقة اليدوية، الطفل والأب، مخزون المواقع، فشل BoM وتمثيل أسعار المتغيرات. جميع العملاء وهميون، و`sync-runtime` مستبدل صراحة لتجنب اتصالات قواعد البيانات.

| الفحص | النتيجة |
|---|---|
| `npm run type-check` | ناجح، exit 0 |
| `npm run lint` | ناجح، exit 0؛ تحذيرات lint موجودة |
| `npm test -- --ci --runInBand --silent` | ناجح: 108 مجموعات، 1368 اختباراً؛ أُعيد بعد آخر تصحيح لكمية BoM |
| `npm run build` | ناجح، exit 0؛ توليد 39 صفحة ثابتة وإتمام build traces |
| `git diff --check` | ناجح؛ تنبيه Git الخاص بتطبيع LF/CRLF ليس خطأ whitespace |

بناء الإنتاج جرى بقيم بيئة مؤقتة غير إنتاجية وحظر الاتصالات الخارجية عدا تنزيل خطوط البناء، مع تعطيل المشغلات. ملفات `.env` لم تُعدّل. تم أيضاً التحقق من احتواء حزم الخادم المبنية على تصحيح كمية BoM الأخيرة وحارس مواقع المخزون، ثم أُعيد الاختبار الشامل. الأدلة المحلية في `%TEMP%/zid-products-{typecheck,lint,tests,build}-final.log`.
